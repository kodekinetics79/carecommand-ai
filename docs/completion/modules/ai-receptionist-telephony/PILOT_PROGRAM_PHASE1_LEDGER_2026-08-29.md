## 1. Executive summary

**Pilot-readiness verdict: NOT READY for a customer-independent pilot.** All seven delivered areas returned BELOW_STANDARD. The compliance/governance core (canonical E.164 + DB CHECK, tenant advisory locks, immutable attested intake contract, hashed disclosure + idempotent consent, HMAC webhooks, drift detection, audited DNC revoke) is ahead of every named competitor; the receptionist itself is not.

The five truths that matter:

1. **The agent knows nothing about the clinic.** `workingHours` is validated and stored but has zero runtime consumers **[verified: only `routes.ts:81,278-281,345,376,428,568` and the type at `promptService.ts:52`]**; the prompt renders name/phone/website/location names/timezone only (`promptService.ts:225-231`); no address, hours, open-now, parking, services, insurers or pricing policy. "Are you open?" and "Where are you?" escalate to staff.
2. **The deployment loop cannot close.** The Export tab emits a webhook with `?clinicId&campaignId` **[verified `promptService.ts:574`]** while verification requires strict equality with the bare URL **[verified `routes.ts:105-107`, `retell.ts:758`]** -> `webhook_mismatch` forever. Verification expires every 24h and `probeRetellAgent` has exactly one caller **[verified `routes.ts:778`; no receptionist verification job in `server/workers/`]**. Mock keys return `mock_not_verifiable` **[verified `retell.ts:670`]**, so no demo or e2e can verify or dial.
3. **Booking works only for "exactly one".** One active provider (`liveTools.ts:119-122` **[verified]**), one eligible location (check_availability schema has no `location_id` **[verified `promptService.ts:481-485`]** while `routes.ts:2999-3002` demands it), one service (schema `const`), one ACTIVE attested campaign (**[verified `routes.ts:2796-2812`]**; prod's only campaign is PAUSED). Every ordinary multi-clinician clinic degrades to staff tasks.
4. **The human loop is unwired.** The staff queue drops caller name/phone/message **[verified `src/lib/apiAdapters.ts:519-540` keeps only `metadata.workflow`]**; tasks get `branchId=null` in multi-branch tenants and are filtered out for branch-scoped staff **[verified `liveTools.ts:112-115`, `operations/routes.ts:949-953`]**; nothing notifies anyone; the Activity "Appointments" tab reads `receptionistAppointmentRequest`, which no production code writes **[verified: only count/findMany/update at `routes.ts:541,1215,1236,1819`; the sole `create` is a test]**; the AI Front Desk inbox reads `Conversation`, which nothing outside tests creates **[verified]**.
5. **Failures are invisible.** ClinicPanel/CampaignPanel/IntakeBuilder/TargetList saves are try/finally with no catch **[verified `ReceptionistStudio.tsx:460-472`]**; Zod 400s say "Request validation failed"; the outbound builder posts `''` for optional UUIDs **[verified `ReceptionistStudio.tsx:1537-1542`]** and cannot create a request-only campaign; tool crashes on a non-ISO date reach an unguarded `handleAgentTool` **[verified `routes.ts:3055-3071`]** and become a silent 500.

Architecture is sound; the work is mostly wiring (S/M). Four items are genuinely large: clinic knowledge (M01), Retell push/sync (M04), inbound profile decoupled from outbound campaigns (M06), and the module harness (M51).

## 6. Open questions only the owner can answer

1. **Deployment ownership.** Does CareCommand own the Retell deployment (push/sync, M04, L effort) or stay BYO-agent read-only with a better export checklist (M32, S)? Every competitor owns it; the governance core is built for the read-only model. This decides the shape of the pilot onboarding.
2. **Inbound line topology.** Is the pilot's AI line a dedicated Retell DID forwarded from the public number, or the public number itself ported? Today `ReceptionistClinic.phone` must equal the dialed number exactly (`migration.sql:431-432`) and is also spoken as the public number. Answer decides M38 scope.
3. **Artifact policy for the pilot.** After GRANTED consent, may transcripts/recordings be stored and shown to staff, or does the pilot stay metadata-only? Today GRANTED changes nothing at the provider and the caller is told "metadata-only" (`liveTools.ts:1207,1227`). Decides M10 copy and M60.
4. **First pilot geography and language.** Prod tenant is UK-branded ("Harley Street") while the runtime is en-US/+1/911. Which locale pack ships first (en-GB with 999, or en-US)? Decides M29 ordering and whether A1-F04 (NY default) is a day-one blocker.
5. **Fate of `/ai-receptionist`.** Retire it and route the sidebar/dashboard/CRM/command-palette "missed calls" links to Studio Activity, or make it the Front Desk queue fed from call logs (M18/M49)? Two half-built surfaces cannot both ship.
6. **Insurance boundary.** May the agent state "that plan is on our accepted list" (list membership only, no eligibility/benefits)? Compliance today forbids any insurance answer (`promptService.ts:296`). Decides whether M01 includes acceptedPayers.
7. **Inbound modelling.** Accept the L-effort split of INBOUND_RECEPTION vs OUTBOUND_OFFER (M06) before pilot, or run the pilot inbound-only on a single ACTIVE campaign with the offer sections neutered as an interim?
8. **Process.** Where is the A6 audit, and should A8 be re-run so its gaps/edge moves/pilot blockers are on record?
